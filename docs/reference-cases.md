# 参考案例

主导航的“参考案例”用于积累其他公司的路演、交流、活动听闻和公开资料。同一公司可以有多条不同主题或日期的案例；仅将它作为参考，不会自动创建对接方、合作事项或公司动态，也不改变最近业务活动日期、日历和周报。

## 记录与查找

填写公司或案例主体、案例标题；了解日期、来源说明、来源链接、标签和摘要可选。了解渠道包括路演、交流、活动听闻、公开资料及其他。不确定日期时留空，不用保存日期代替发生日期。

“了解内容”保存听到的介绍、看到的产品和具体来源；“对我们的启发”单独保存判断、可借鉴做法和待核实的问题。两部分均支持 Markdown，可在保存前预览。检索覆盖公司、标题、摘要、正文、启发、来源说明及标签，可按渠道、标签和归档状态筛选。

“照片与资料”可一次选择多张 PPT 照片，或 PDF、PPT/PPTX 等文件。每次最多添加 10 份、单份不超过 50 MB；每条案例最多关联 40 份。文件暂存后随案例一起保存，图片提供缩略图与放大查看，其他文件沿用工作台的预览和下载功能。不会自动识别图片文字或推断内容；文字笔记由成员或获授权 AI 工具整理。

新建、编辑均记录实际操作账号和时间。详情内可查看历史版本及当时附件；工作区历史快照显示当时案例。移除附件关联只改变当前视图，历史原件仍保留。管理员可以归档案例，从常用列表收起，也可以重新启用。

## 访问范围

参考案例是公司层面的资料，第一版复用已有访问范围：管理员及拥有“全部事项”范围的成员可查看；其中管理员和编辑成员可新增、修改，只读成员只能查看。仅被授权指定事项的成员无法访问案例及附件。归档和重新启用由管理员操作。

不会自动为现有成员提升权限。案例保存在 `content/references/<case-id>/README.md`，附件保存在同级 `attachments/` 下，纳入完整备份和恢复。业务附件资料库仍展示事项资料；参考案例附件在案例详情中管理。

## MCP

| 工具 | 用途 |
| --- | --- |
| `search_reference_cases` | 按关键词、渠道、标签及归档状态检索，支持分页及历史快照 |
| `read_reference_case` | 读取完整内容、附件和版本；新增时不传 `id` 取得初始字段与创建版本 |
| `reference_case_history` | 查询修改历史；传 `version` 读取当时内容 |
| `prepare_reference_upload` | 准备照片或文件上传，返回暂存编号及上传路径 |
| `submit_reference_case` | 提交新增或修改草稿，由连接本人在网页确认 |
| `save_reference_case` | 管理员明确启用直接保存的连接正式保存 |

写入前先检索查重，再读取当前版本；服务端阻止公司、日期、标题相同的重复案例，包括已归档案例。新增校验案例集合版本，更新校验该案例和附件的版本；并发修改后须重新读取并核对。

`changes` 支持 `organization`、`title`、`observed_on`、`source_type`、`source_name`、`source_url`、`tags`、`summary`、`body`、`insights`、`attachment_ids`、`archived`。`observed_on` 为 `YYYY-MM-DD` 或 `null`；`source_type` 为 `roadshow`、`exchange`、`event`、`article`、`other`。作者、更新人和保存时间由服务端按实际账号填写，不接受冒名字段。

文件先通过 `prepare_reference_upload` 提交文件名、大小和 SHA-256，再向返回的同源 `/api/mcp/uploads` 上传实际文件字节；使用同一连接凭据，凭据不得进入模型内容。之后将暂存编号放入写入请求的 `attachments`，其条目包含 `upload_id`、`title`，可选 `category` 和 `note`。只提供电脑上的路径不代表文件已上传。现有 `upload_status`、`discard_upload` 可查询或放弃暂存。

草稿及直接保存均传入 `revision` 和至少 16 位的唯一 `request_id`。重试保留相同编号和内容；结果不确定时先回读核对，不能换编号盲目重试。成功后用 `read_reference_case` 核对正文、附件和账号信息。草稿确认时再次校验权限、版本及暂存文件归属。
