# 补充记录

与某条沟通进展相关的介绍文案、分析和背景资料，保存在该进展详情底部的“补充记录”。事项下所有类型的沟通进展均可添加补充，包括初次接触、会议、方案、协议、付款和其他进展；没有完整正文的简短进展也可使用。

每条补充独立保存，可填写标题，正文支持 Markdown，并记录补充日期、创建账号和最近编辑账号。

- 新增或修改补充不会修改原进展日期、正文、参与人和原记录更新人。
- 补充不进入业务时间线、动态日历，不计作新的会议或沟通，也不更新事项的最近业务活动日期。
- 发送资料、收到回复、约定下次会议等新发生的业务动作，继续新增独立进展。
- 管理员和获授权事项的编辑成员可新增、修改补充；只读成员可查看。历史只返回所属事项内该条补充的内容。
- 历史工作台显示所选快照中的补充，不混入之后新增或修订的文字。历史内容只读。

## 操作

打开事项 → “查看进展”或“阅读完整记录” → 底部“添加补充”。保存后可以继续添加多条补充，或使用“编辑补充”“修改历史”。编辑时发生版本冲突会保留输入，可读取最新版本并比较后再保存。

在记录详情选择“导出 PDF”，可勾选“附上补充记录”。导出保留原进展与补充各自的日期、作者和正文。

## MCP

- `read_progress_supplements`：指定 `matter_id`、`progress_id`，返回补充列表和创建版本；传 `id` 返回单条正文及编辑版本。可传 `snapshot` 读取历史快照。
- `progress_supplement_history`：指定事项、进展和补充 ID，分页读取历史，或传 `version` 回读某次保存的完整内容。
- `submit_progress_supplement`：提交新增或修改草稿，由本人在网页确认。
- `save_progress_supplement`：仅对已明确启用直接保存的管理员连接开放。

新增前先通过 `read_progress` 读取所属进展，再读取已有补充，避免重复。写入字段为 `changes.date`、`changes.body` 和可选 `changes.title`；修改只合并提供的字段。使用最近读取的 `revision` 和稳定的 `request_id`，超时重试保持工具名称及全部参数不变。结果不确定时先回读并检查历史，不换请求编号盲目重试。作者由服务端按凭证所属账号记录，客户端不能指定。

现有客户端的 `read_meeting_supplements`、`meeting_supplement_history`、`submit_meeting_supplement` 和 `save_meeting_supplement` 仍可调用，参数继续使用 `meeting_id`，权限和保存规则与新接口相同。新连接发现的工具列表使用通用名称。已有待确认草稿、保存回执和历史记录继续有效，无需迁移资料。

## 存储与资料整理

补充保存为所属事项下 `supplements/supp-<id>.md`，通过 `event_id` 关联进展。文件随现有资料备份、恢复和历史快照保存。

若某段补充曾临时保存为独立进展，先在原记录下添加补充并核对完整文案和日期，再由管理员将重复进展移入回收站。原独立进展及其历史可恢复。

已有专项迁入服务继续供管理员处理同一事项中标题以“会后补充：”开头的临时记录，不增加日常页面入口。有附件、补充或问答引用的来源记录会拒绝迁入。开发验证完成与正式上线分别核对。
