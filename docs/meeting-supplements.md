# 会后补充

会后整理的介绍文案、分析、背景资料放在原会议底部的“会后补充”。每次补充独立保存，可填写标题，正文支持 Markdown，并记录补充日期、创建账号和最近编辑账号。

- 原会议保留当时的内容。新增或修改补充不会修改会议日期、正文、参与人和原记录更新人。
- 补充不进入业务时间线、动态日历，不计作会议，也不更新事项的最近业务活动日期。
- 发送资料、收到回复、约定下次会议等新发生的业务动作，继续新增独立进展。
- 管理员和获授权事项的编辑成员可新增、修改补充；只读成员可查看。修改历史只返回所属事项内该条补充的历史内容。
- 历史工作台读取所选快照中的补充，不混入之后新增或修订的文字。历史内容只读。

## 操作

打开事项 → 阅读会议完整记录 → 底部“添加补充”。保存后可以继续添加多条补充，或使用“编辑补充”“修改历史”。编辑时发生版本冲突会保留输入，可读取最新版本并比较后再保存。

已有临时进展的迁入属于专项资料整理，不在日常页面设置入口。迁移服务仅接受管理员操作，限定同一事项中标题以“会后补充：”开头的临时进展。执行前核对全文及来源版本，原样保留正文和日期，移除重复时间线记录并留存前后历史。有附件、后续补充或问答引用的记录会拒绝迁入。

## MCP

- `read_meeting_supplements`：指定 `matter_id`、`meeting_id`，返回补充列表和创建版本；传 `id` 返回单条正文及编辑版本。可传 `snapshot` 读取历史快照。
- `meeting_supplement_history`：指定事项、会议和补充 ID，分页读取历史，或传 `version` 回读某次保存的完整内容。
- `submit_meeting_supplement`：提交新增或修改草稿，由本人在网页确认。
- `save_meeting_supplement`：仅对已明确启用直接保存的管理员连接开放。

新增前先读取会议和已有补充。写入字段为 `changes.date`、`changes.body` 和可选 `changes.title`；修改只合并提供的字段。使用最近读取的 `revision` 和稳定的 `request_id`，超时重试保持参数不变。结果不确定时先回读并检查历史，不换请求编号盲目重试。作者由服务端按凭证所属账号记录，客户端不能指定。

## 存储与迁移

补充保存为所属事项下 `supplements/supp-<id>.md`，通过 `event_id` 关联会议。文件随现有资料备份、恢复和历史快照保存。部署前应备份工作区及历史库，并在副本中验证迁入。开发测试完成不等于已发布或已迁移线上资料。
