# 外部 AI 工具接入（MCP）

团队模式下可选的 MCP Streamable HTTP 接口，默认关闭。与内置 AI 独立，不需要在服务器安装外部 AI 客户端，也不调用 BD 配置的模型。使用者的 AI 工具处理模型请求；BD 提供获授权资料、草稿服务，以及管理员明确授权的业务录入功能。

接入能力取决于客户端是否支持远程 MCP（Streamable HTTP）和个人 Bearer 凭据认证，与采用哪个模型无关。不能仅凭工具使用 Claude、DeepSeek、豆包等模型就判断它能否连接。当前不提供 OAuth 登录；只支持 OAuth 或本地 stdio 的客户端不能直接使用此连接方式。

## 使用方式

1. 部署团队模式，配置 HTTPS 与 `BD_PUBLIC_URL`，按邀请流程创建账号并完成密码、TOTP 设置。远程接口使用 BD 网站的 HTTPS 地址和端口。
2. 管理员进入「管理中心 → AI 设置 → 外部 AI 工具」，开启全局功能；管理员自动具备接入资格，无需为自己单独授权。普通成员默认不允许，在「成员与权限」邀请或调整时勾选「允许连接外部 AI 工具」。功能关闭时也可以预先分配权限，但不能连接或生成凭据。
3. 成员登录「我的账号 → AI 工具连接」，生成个人凭据。邀请只分配权限，不生成、共享或在邀请链接中附带工具凭据。连接默认提交草稿；只读成员默认且仅可查询。管理员可主动选择「允许直接保存进展及附件」，已有仅查询或草稿连接不会自动获得直接保存权限。有效期下拉提供 1 天、7 天（默认）、14 天、30 天，每个成员最多 5 个有效凭据。
4. 凭据只显示一次，服务端仅保存 SHA-256 摘要。按客户端支持的方式存入本人设备的凭据设置或环境变量。不要把值输入模型对话、代码、网页 URL、共享配置或服务器访问日志。
5. 在客户端的 MCP 设置中填写服务地址 `https://bd.example.com/api/mcp`（替换为自己的 BD 域名），将个人凭据配置为 Bearer Token，即 HTTP `Authorization: Bearer <个人凭据>`。具体配置入口以所用客户端为准。

### Codex 配置示例

按 [Codex 官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp) 配置。将凭据保存到本人电脑的环境变量 `AIRALOGY_BD_TOKEN`，并让启动 Codex 的进程能够读取。macOS 图形应用不一定继承终端变量；配置中的变量名不是凭据本身。

```toml
[mcp_servers.airalogy_bd]
url = "https://bd.example.com/api/mcp"
bearer_token_env_var = "AIRALOGY_BD_TOKEN"
```

CLI 也可以通过 `codex mcp add airalogy_bd --url https://bd.example.com/api/mcp --bearer-token-env-var AIRALOGY_BD_TOKEN` 添加。地址换成自己的 BD 域名，凭据不能共用。重新连接后，可让外部 AI 工具查询某个事项或整理一次实际进展。

### 草稿与直接保存

提交草稿后，外部工具获得草稿编号和 `/remote#draft-...` 路径。本人进入 BD「待确认修改」，刷新，核对事项、日期、事实状态与全部前后差异，勾选确认，再点击「确认并正式保存」。可以驳回；需修改草稿时先驳回旧稿，再让外部工具重新提交。

管理员明确选择「允许直接保存进展及附件」的连接会额外获得 `save_progress` 工具。它可直接新增、修改已有事项的进展，并一并保存关联附件，无需再次网页确认；`submit_draft` 始终只生成草稿，即使连接有直接保存权限，该草稿及其附件仍需网页确认。上传仅暂存文件，只有正式保存后才进入资料库。修改事项正文、阶段或下一步仍须提交草稿，管理员另行授权“新建事项及维护业务档案”后，可通过录入方案维护事项及共享档案；删除仍在网站完成。

## 功能范围

| 工具 | 能力 |
| --- | --- |
| `search_entities` | 查询人员或对接方的基本身份和关联事项，按账号范围过滤，不返回联系方式 |
| `read_entity` | 业务档案维护连接读取完整人员或对接方档案及版本 |
| `prepare_intake` | 准备人员、对接方、一个事项及一条进展的完整录入方案，不写入业务资料 |
| `submit_intake` | 将录入方案及附件提交网页确认 |
| `save_intake` | 同时具备业务档案维护和直接保存权限的管理员连接，一次正式保存方案及附件 |
| `discard_intake` | 丢弃尚未用于草稿的录入方案 |
| `search_matters` | 按事项、对接方名称或简称搜索本人获授权的已有事项，20 条一页 |
| `read_matter` | 读取一个获授权事项的正文、阶段、跟进状态、下一步、参与人 ID、版本及进展摘要（分页） |
| `read_progress` | 读取某事项下的一条进展正文、字段及进展附件引用 |
| `list_files` | 查询获授权事项的在用资料元数据，20 条一页 |
| `read_file` | 查询资料版本、文件指纹、明确记录的状态和协议日期，版本按最新在前分页 |
| `prepare_upload` | 申请绑定当前账号、连接、权限版本及事项的暂存上传 |
| `upload_status` | 检查当前连接的上传是否完成 |
| `discard_upload` | 移除未用于草稿的暂存上传；不会删除归档资料 |
| `submit_draft` | 提交草稿：对已有事项新增进展、修改已有进展，或修改事项正文、阶段、跟进状态、下一步及日期 |
| `save_progress` | 仅限管理员明确授权的连接，正式新增或修改已有事项的进展及其附件，返回进展编号、当前版本及历史版本 |

删除、账号管理、模型密钥、备份不在远程工具中开放。完整人员档案（包括已有联系方式）、新建事项和共享对接方档案仅向明确授权业务档案维护的管理员连接开放；普通成员继续按原事项权限查询身份及关联事项、提交进展草稿。附件仅支持查询元数据，以及随进展关联已有版本、归档新文件或追加版本；不提供任意服务器文件读取、远程 URL 抓取或附件正文读取工具。正文中由业务人员自行写入的敏感信息仍会随正文返回；模型服务的数据使用政策仍需符合公司的要求。客户端的工具审批提示只是额外保护，不能替代服务端权限。

修改前先查询已有事项并确认目标；无法确定时向用户澄清，不能猜测事项或业务事实。新增进展使用 `read_matter` 返回的版本，修改进展使用 `read_progress` 的版本，修改事项使用 `read_matter` 的版本。

两种提交工具的 `revision` 使用上述版本，`request_id` 使用唯一 UUID。相同凭据、相同请求编号、相同内容的重试只返回原收据；同编号不同内容、在草稿与直接保存工具间混用编号均拒绝。已保存收据不会再次执行。草稿收据最长保留 24 小时且不超过凭据有效期；直接保存收据保留至该凭据到期。每人最多 20 份待处理草稿，全局最多各 2000 份有效期内草稿收据和直接保存收据；超限需等待到期或撤销不再使用的凭据。每个账号每分钟最多 60 次接入认证/服务调用，工具调用包含入口校验和执行校验两次。

## 完整业务录入

管理员在“我的账号 → AI 工具连接”生成凭据时，可另行勾选“允许新建事项及维护业务档案”；已有可写连接需由本人点击“授权业务档案维护”并明确确认，升级不会自动扩大旧凭据权限。草稿连接仍只能提交草稿；同时开启直接保存的连接才能调用 `save_intake`。

1. 使用 `search_entities` 搜索人员与对接方，结合 `search_matters`、`read_matter`、`read_progress` 检查已有事项和历史。返回的候选不是身份结论，有歧义应询问用户。
2. `prepare_intake` 接收顺序排列的 `operations`，每项包含唯一 `ref`、`kind` 和 `changes`。已有记录必须提供 `id` 与读取到的 `revision`；新记录不填。关系字段可用 `@ref` 引用前面创建的人员、对接方、事项。业务正文不会按引用处理。
3. 新事项需提供归档对接方、事项名称、联系人关系及 `initial_event`；会议须有日期、标题、摘要和整理后的正文。首次接触日期与来源未知时保持未知，不将会议日期视作首次接触，不虚构负责人或期限。返回完整核对内容和稳定编号，尚未保存。
4. 新事项的附件申请同时传入返回的 `matter_id` 和 `intake_id`，按下节上传实际文件。附件绑定本账号、连接、录入方案与进展，不能借未保存的事项访问其他资料。
5. 调用 `submit_intake` 或 `save_intake`，传入 `intake_id`、唯一 `request_id` 和可选 `attachments`。人员、对接方、事项、进展和资料索引一并验证、一次留存历史；草稿在网页展示全部字段差异与附件供核对。

每个方案最多 12 项修改，只处理一个事项和一条进展，也可单独维护人员或对接方。每个账号最多保留 20 个未完成方案，有效期最长 24 小时且不超过凭据期限。准备后任何业务资料变化都会阻止旧方案保存，需重新读取后准备；不会覆盖同事的新修改。相同保存编号及内容返回原收据，不重复创建。方案、草稿及请求收据绑定凭据，撤销、权限变化和关闭功能时一并失效，并从账号备份中排除。正式业务内容直接记录事实、体验、判断及下一步，不把录入者的核对说明写进正文或附件备注。

## 进展附件

先用 `list_files`、`read_file` 确认是否已有同一份协议。`submit_draft` 和 `save_progress` 可传入 `attachments`（最多 10 项），仅用于新增或修改进展：

- 关联已有版本：`{"mode":"existing","file_id":"...","revision":"...","version_id":"..."}`。版本必须明确指定，文件必须已关联本事项，且使用者须拥有文件全部关联事项的权限。
- 导入新文件：`{"mode":"upload","upload_id":"...","title":"协议名称","category":"agreement","agreement_type":"nda","status":"draft"}`。
- 追加版本：`{"mode":"version","upload_id":"...","file_id":"...","revision":"...","status":"signed","agreement_date":"2026-01-10","signing_completed_date":"2026-01-15"}`。示例日期和状态仅用于说明格式，实际值须来自用户明确提供的事实。

`revision` 来自 `list_files` 或 `read_file`。上传／追加版本可提供 `status`、`note`；协议还可提供 `agreement_date` 与 `signing_completed_date`，允许留空或不同。上传或关联本身不会推断发送、签署或事项阶段。附件仅追加关联；本接口不删除文件或移除既有关系。

实际文件传输步骤：

1. 客户端从用户明确提供的本地文件计算字节数和 SHA-256，调用 `prepare_upload`（`matter_id`、`filename`、`size`、`sha256`）。
2. 用同一 Bearer 凭据向**同一 BD 服务地址**的 `/api/mcp/uploads` 发起 `multipart/form-data` POST，包含 `upload_id` 和二进制 `file`。使用 `prepare_upload` 返回的相对路径，禁止把凭据转发到其他域名。凭据从客户端安全配置读取，不写入模型对话；文件字节也无需作为 Base64 填进 MCP 对话。
3. 收到 `ready: true` 后，将 `upload_id` 放入上述附件参数。网络中断时可用 `upload_status` 核对，重传相同编号、文件名、大小和指纹的内容不会新增文件。
4. 草稿模式下，进展和附件先一起展示给本人；网页可下载暂存文件核对，再一起确认。直接保存模式下，管理员的连接可一并归档，重复保存请求返回原收据。

客户端需要具备读取本地文件并执行 HTTP 文件传输的能力。仅支持文字工具调用的客户端不能自动完成文件上传；文件路径或对话中添加的附件不会自动变成 BD 文件。此时可在 BD 页面上传，再通过 MCP 查询和关联已有版本。

每个文件最大 50 MB；每个账号最多 20 个／250 MB 有效暂存文件（含上传申请），每个工作区总量最多 1 GB。上传最长保留 24 小时且不超过凭据有效期，草稿有效期不超过其附件。文件位于私有 `.bd-history/<工作区标识>/uploads/`，不进入业务索引、内容 Git 历史或工作台完整备份。失效后不可访问，在后续工作区检查或上传操作中清理；已归档文件沿用原有版本保留及备份规则。取消权限、撤销连接或关闭功能后，旧上传立即无法通过该连接访问。

进展、资料索引和版本关联经过同一校验及事务保存。校验失败不会留下一条没有附件的进展；原件不可覆盖。单条进展恢复会恢复该进展的附件引用，保留归档文件及其他进展的引用；不会抹除附件原件。

## 权限与保存保障

- 管理员开关和成员授权使用账号登录、TOTP、CSRF 与管理员权限。邀请与外部工具授权在同一事务中保存；调整成员权限检查资料版本，尚未接受的邀请保留原链接和到期时间。成员自行签发凭据，管理员可以撤销任何凭据；成员只能撤销自己的凭据。
- 管理员的接入资格随角色生效，不保存为普通成员授权；改为普通成员时默认不保留，可按需重新授权。资格本身不会开启全局功能、生成凭据或授予连接直接保存权限。直接保存需在新建连接时主动选择，服务端每次仍检查管理员身份和该连接的权限。
- 每次请求检查全局开关、授权、账号启用状态、账号权限版本、凭据有效期和具体事项权限。修改权限、停用账号、重置登录将撤销该成员凭据、草稿和保存请求收据；取消远程授权也会撤销。退出网页登录不会撤销已签发的独立远程凭据，请在凭据列表撤销。
- 关闭功能撤销全部凭据、草稿和保存请求收据，保留成员授权；重新开启后必须重新生成凭据。个人凭据不具备网页会话权限，不能调用网页确认接口；网页 Cookie 也不能充当 MCP 凭据。
- 草稿绑定提交账号、凭据和权限版本，只能由同一账号在网页确认，管理员不能代替他人确认。确认时再次检查权限、草稿有效期和原资料版本。
- 所有操作经过同一工作区锁；正式保存复用数据服务、事务日志、版本记录和审计。确认接口只取服务端保存的草稿，忽略客户端额外提交的业务字段。确认一次后不能重放。
- 正式保存前先持久化「处理中」收据，再修改业务资料。若文件保存与收据更新之间中断，直接保存返回 `uncertain`（结果待核对）；相同请求不会再次执行。保留原请求编号，在工作台及修改历史中核对结果，不能换一个编号盲目重试。保存前检测到版本冲突则拒绝写入，需先读取最新资料再整理修改。
- 管理员可在“修改历史”中比较并恢复单条进展，无需回滚整个事项。恢复本身产生新记录，并检查当前版本；恢复前需要核对是否影响后续人工修改。回退不能撤回已发送给模型的内容，因此不作为开放直接保存的依据。

远程设置、哈希凭据、短期草稿及保存请求收据保存在私有 `.bd-auth/accounts.sqlite3`（目录 0700、文件 0600），不进入代码仓库或业务内容历史。草稿正文按业务数据保护，不宣称数据库静态加密。账号备份清除远程设置、普通成员授权、凭据、草稿、保存请求收据及限流状态，恢复后默认关闭；审计保留操作类型、账号、凭据/草稿/保存请求编号和结果，不包含原始凭据或草稿正文。外部工具的模型费用不计入内置 AI 用量报表。

## HTTP 协议与运维

`/api/mcp` 提供无会话的 JSON 响应式 Streamable HTTP，支持协议版本 `2025-03-26`、`2025-06-18`、`2025-11-25`；无需长连接。初始化、列工具、调用工具及通知均要求有效凭据。GET/DELETE 在校验授权后返回 405，不提供 SSE、资源订阅或服务端推送。批量 JSON-RPC 请求不支持。

接口检查 Host、Origin（存在时）、请求格式、协议版本、24 KB 请求上限，且不允许跨站请求。网页登录独立执行 CSRF 校验。反向代理只转发到本机应用端口，按部署示例设置登录/请求限流，并对 `/api/mcp` 与 `/api/mcp/uploads` 限制连接数和请求速率。MCP 消息仍限制为 24 KB；独立上传路由按 50 MB 文件加少量表单开销限制请求体，不提高 MCP 消息上限。代理必须保留正确 Host、Authorization，禁止记录 Authorization/Cookie。无需把 `.bd-auth`、数据目录或管理端口暴露到互联网。

接口遵循 [MCP Streamable HTTP 规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。自动测试覆盖真实 HTTP、邀请时分配外部工具权限、待激活成员权限调整、TOTP 会话、默认关闭、角色/事项边界、凭据生命周期、草稿确认、管理员直接保存、重复请求、处理中断、并发冲突、单条恢复和停用。每次部署后仍需使用本人账号，按上述步骤完成实际客户端连接验收。
